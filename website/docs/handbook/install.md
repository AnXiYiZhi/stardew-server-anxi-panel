# 安装游戏

"安装"页负责把 Stardew Valley 专用服务器（JunimoServer）装进面板管理的 Docker 环境，也是管理员保存和修改 Steam 账号密码、按需启用 Steam 邀请码的入口。

## 首次安装

1. 填写 **Steam 账号**、**Steam 密码**、**VNC 密码**（VNC 密码用于后续通过浏览器画面查看游戏窗口，不是 Steam 密码）。
2. 点击开始安装。面板会依次执行：
   - 拉取 JunimoServer 相关 Docker 镜像。
   - 使用 SteamCMD 和你填写的账号下载 Stardew Valley（Steam App 413150）。
   - 使用 SteamCMD 匿名会话下载 Steamworks SDK（Steam App 1007）。
   - 校验并安装 SMAPI，再同步 Junimo/Control 所需的内置支持文件。
   - 验证游戏、SMAPI 与 Steam SDK 运行文件完整。
3. 全部完成后回到"总览"或"服务器"页启动服务器；不启用 Steam 邀请码也可以直接使用局域网/IP 联机。

整个过程页面会实时展示当前阶段和下载进度。安装日志按倒序显示，**最上方是最新一条**；接口和任务中心仍保存完整的时间顺序。

::: tip 默认安装不会启动 Auth
全新实例的 Steam 邀请码默认关闭。基础安装不会拉取、创建、启动或探测 `steam-auth`，Auth 缺失不会影响安装完成、启动、存档、Mod、备份或局域网/IP 直连。SteamCMD 只是安装/修复下载工具，不是服务器日常运行组件。
:::

从 v0.4.11 起，同一实例同一时间只会有一个安装或 Steam 授权任务。如果不小心连续点击、刷新页面后再次提交，或者另一个管理员同时操作，面板会自动回到已经存在的任务并继续显示同一份进度与日志，不会重复下载。任务成功、失败或取消后会以持久化终态为准，旧日志不会再让页面重新显示成“正在下载”。

## Steam Guard 验证

如果 Steam 账号开启了两步验证，SteamCMD 安装过程中会暂停并提示以下方式之一（具体哪种取决于账号的验证方式）：

- **手机 App 批准**：直接在手机 Steam App 上点确认，不需要输入验证码。
- **App / 邮箱验证码**：把 Steam 发来的验证码填入面板提供的输入框提交。

提交验证码后页面会先显示"验证码已提交，正在等待 Steam 响应"，不会立刻消失或报错；如果长时间没反应，页面提供"重新输入"按钮。

取消登录、认证超时或 Panel 在认证过程中停止时，已经下载的游戏数据和其它实例不会因此被误删；稍后可以继续同一个实例的安装或修复。

::: tip 为什么正常只需批准一次
游戏本体使用你填写的 Steam 账号下载；Steamworks SDK 固定使用匿名登录。因此正常情况下，一次安装最多只需要批准一次 Steam Guard。
:::

## SteamCMD 授权缓存与修复

SteamCMD 首次完整登录成功后会保存自己的授权缓存。以后执行“校验 / 修复安装”时优先使用该缓存；缓存无法继续使用时，Panel 会先自动尝试当前已保存的账号密码，只有 Steam 要求二次验证时才提示 Steam Guard，保存的凭据被拒绝时才需要管理员修改。客户端自更新、缓存文件存在或日志出现登录进度都不会被单独当成授权成功，最终仍以 SteamCMD 的真实结果为准。

## 国内网络：SMAPI 加速与断点续传

从 v0.4.5 起，SMAPI 安装包不再只等待 GitHub 官方整包下载。Panel 会按照受审固定顺序尝试 `gh.llkk.cc`、`github.dpik.top`、`ghfast.top`，最后由 GitHub 官方地址兜底：

- 安装包按 2 MiB 分块下载。单段超时、断流或短时网络波动后，会从已经收到的位置继续，不会每次都从零开始。
- 当前候选连续没有进展时才切换下一项；任务日志会显示正在使用或回退到哪个候选。
- 下载完成后必须同时通过固定大小、SHA-256 和 ZIP 结构检查。代理返回网页、残缺包或被替换的内容都会被拒绝并清空，不会进入安装步骤。
- 为防止任意代理绕过校验，运行时不会采用 `.env` 中自定义的 `SMAPI_DOWNLOAD_URLS`。完全离线环境应由管理员提前放入经过同样校验的安装包。

::: tip 之前卡在 SMAPI 的实例
先把 Panel 更新到最新版，再回到“安装”页使用“重新安装 / 修复”。已经完成的游戏本体和 SDK 不会重新下载，任务会直接继续校验并安装 SMAPI。
:::

## 修复 / 重新安装

已安装过的实例，安装页会显示“校验 / 修复安装”入口，用于游戏文件损坏、下载中断等情况：

- 面板优先使用仍然有效的 SteamCMD 授权缓存；缓存无法继续使用时，才自动尝试当前保存的账号密码，并仅在 Steam 要求时提示 Guard。
- 已下载的游戏文件不会被清空重来，SteamCMD 会校验已有文件，只重新下载有问题的部分。
- 修复安装不会启用 Steam 邀请码，也不会删除已经有效的 SteamAuth session。

## 修改 Steam 账号密码

管理员可以在实例已经安装且服务器停止时，使用“修改 Steam 账号密码”更新 Panel 保存的 Steam 凭据：

- SteamCMD 安装/修复与 Steam 邀请授权共用这组账号密码；表单不要求重新填写 VNC 密码。
- 保存只更新凭据，不会立即启动安装或 Auth 授权任务。
- SteamCMD 授权缓存与 SteamAuth session 是两份独立材料。只要各自仍然有效，就会继续优先复用；修改账号密码不会主动删除它们，也不会清空游戏数据。
- SteamCMD 无法继续使用自己的缓存时，才会回退到当前保存的凭据；已经成功保存的 SteamAuth session 不会因为修改账号密码被主动替换或重新授权。

## 按需启用 Steam 邀请码

全新实例默认只提供局域网/IP 直连。需要 Steam 邀请码时，管理员先停止服务器，再在安装页点击“启用 Steam 邀请码（需要再次登录授权）”：

1. Panel 此时才检查并按需拉取 SteamAuth 镜像，启动一次性授权容器。
2. 按页面提示完成二维码、手机批准或 Guard 验证。SteamAuth 只负责邀请码授权，不会再次下载游戏本体。
3. 授权成功后保存 session，并停止这次登录用的授权容器。以后启动服务器时，Panel 才会同时维护 Auth sidecar 并获取邀请码。

授权失败可以在停服后重试，只会更新邀请码能力的状态，不会把已经完成的基础安装改成失败，也不会删除 SteamCMD 缓存或 `game-data`。启用后，邀请码卡可能依次显示等待授权、服务器未运行、正在生成、已就绪，或 Auth 异常；即使 Auth 暂时异常，局域网/IP 直连仍可使用。

::: tip 旧实例升级
升级到 v0.6.0 后，历史上已经成功完成 Steam 邀请授权或已有邀请码能力的实例会继续保持启用；只有普通安装或 SteamCMD 证据、从未启用邀请码的实例保持关闭。升级不会主动清除已有的有效 session 或授权缓存。
:::

## 安装失败常见现象

| 现象 | 说明 |
| --- | --- |
| JunimoServer 镜像拉取失败 | 检查 Docker 与镜像网络后重试安装；不会因此改走 SteamAuth |
| SteamCMD 授权缓存不可用 | Panel 会先自动使用当前保存的账号密码；Steam 要求时再完成 Guard，凭据被拒绝时再修改账号密码 |
| 启用邀请码时 Auth 镜像或登录失败 | 基础安装仍保持完成，局域网/IP 直连仍可用；停服后可再次点击启用入口重试 |
| SMAPI 安装失败 | 先更新到 v0.4.5 或更高版本，再直接重试“重新安装 / 修复”；游戏文件、SDK 和已通过的 Steam 认证不受影响 |
| 重复点击后提示已有安装任务 | 这是 v0.4.11 的防重复保护；页面会接管同一个任务，不需要再提交一次 |

更多报错现象和解决办法看 [常见问题](/faq/)。

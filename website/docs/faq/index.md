# 常见问题

按现象查找对应小节。如果本文没有覆盖你的问题，先按 [面板管理与诊断](/maintain/admin) 里的"导出诊断包"收集信息，再反馈。

如果现象比较特殊（例如存档突然回退、小屋箱子打不开、节日卡住），也可以先看 [已知问题（上游）](/faq/known-issues)，确认是否命中 JunimoServer 上游已知 Bug。

## 面板打不开 / 容器起不来

- 确认端口 `8090` 没有被其他程序占用；改用其他宿主机端口重新运行（一键脚本可在菜单里改端口，手动 `docker run` 时改 `-p 9090:8090`）。
- 确认启动命令挂载了 Docker Socket：`-v /var/run/docker.sock:/var/run/docker.sock`，否则面板无法控制游戏容器。
- NAS 图形界面如果不允许挂载 `/var/run/docker.sock`，面板无法正常工作，需换支持 Docker Socket 挂载的部署方式。

## 安装卡住不动 / 镜像拉取失败

- 全新实例默认走 SteamCMD 安装主链：拉取 JunimoServer 镜像，下载 Stardew Valley（App 413150）和 Steamworks SDK（App 1007），再准备 SMAPI、Junimo/Control 并校验。默认安装不会拉取、启动、探测或轮询 SteamAuth。
- JunimoServer 镜像保留 6 个内置候选（dockerproxy.net、1ms、1panel、jiaxin、dockerproxy.link 与 Docker Hub），单个源失败会自动尝试下一个，任务日志会按实际列表显示 `(1/6)` 这样的候选进度。只有管理员明确启用 Steam 邀请码时，Panel 才会按需检查 Auth 镜像候选。
- 如果所有候选都失败，通常是服务器整体出网络问题（DNS 解析失败或被墙）。面板内置了 DNS 自愈（系统解析失败会自动换用公共 DNS），但如果服务器完全不能访问公网 DNS 53 端口，这个自愈也无法生效，需要联系服务器提供商或检查防火墙。
- 家用 NAS 如果路由器 DNS 不稳定，也可能导致 Nexus 搜索、Docker Hub 版本检查间歇性失败，现象和上面类似。
- v0.4.11 起，连续点击安装或另一个管理员同时提交时，页面会接管同一个活动任务。看到“已有安装任务”不是新故障，不要继续反复点击；等待同一任务终态或查看它的日志即可。

## SteamCMD 安装登录 / Steam Guard 一直卡住

- 首次安装使用 SteamCMD 登录并下载游戏本体；如果 Steam 要求二次验证，页面会显示手机 App 批准提示或 Guard 验证码输入框，按提示操作即可。
- SteamCMD 登录成功后会保存自己的授权缓存。以后校验或修复安装时优先复用仍有效的缓存；只有缓存无法继续使用时，才会自动尝试当前保存的账号密码，并在 Steam 要求时提示 Guard。
- 已安装实例需要换凭据时，由管理员先停服，再在“安装”页使用“修改 Steam 账号密码”。保存只更新 SteamCMD 与 Steam 邀请授权共用的账号密码，不会立即运行安装或授权任务，也不会主动清除仍有效的 SteamCMD 缓存、SteamAuth session 或游戏数据。
- 如果首次安装尚未完成，直接在安装表单里检查账号密码并重试；已经下载成功的文件会由 SteamCMD 校验复用，不会因为一次登录失败全部清空。

## 启用 Steam 邀请码时授权卡住或失败

- 只有管理员可以启用邀请码，而且必须先停止服务器，再到“安装”页点击“启用 Steam 邀请码（需要再次登录授权）”。普通用户看不到这个入口。
- Panel 只在此时按需拉取 Auth 镜像并启动一次性授权容器。按页面提示完成二维码、手机批准或 Guard 验证；成功保存 session 后，这个登录容器会停止。SteamAuth 只负责邀请码授权，不会重新下载游戏本体。
- 授权失败或授权容器清理异常只会更新 Steam 邀请码能力的状态，不会把已完成的游戏安装改成失败，也不会删除 SteamCMD 缓存或 `game-data`。局域网/IP 直连仍可正常使用。
- 修改 Steam 账号密码不会让已经有效的 SteamAuth session 主动失效，也不会主动替换已授权的 Steam 身份；v0.6.0 不会为了切换账号而重复登录一个已经完成授权的 session。

## 游戏和 SDK 已完成，但 SMAPI 安装失败

- 先在“诊断”页确认 Panel 已更新到 v0.4.5 或更高版本。旧版本从 GitHub 整包下载 SMAPI，国内低速链路可能在两分钟后稳定超时。
- 新版本会依次尝试三个受审加速地址，最后回退到 GitHub 官方；下载支持分块续传。回到“安装”页点击“重新安装 / 修复”即可，不需要重新认证 Steam，也不会清空已下载的游戏和 SDK。
- 日志出现某个候选失败并继续下一候选是正常回退。只有全部候选都失败时，才需要检查服务器 DNS、HTTPS 出站网络、磁盘空间和系统时间。
- 不要通过 `.env` 临时加入陌生下载代理。Panel 会拒绝未受审 URL，并对最终安装包执行固定大小、SHA-256 和 ZIP 结构校验，这是防止代理返回错误或被替换文件的安全门槛。

完整下载机制与修复入口见 [安装游戏：SMAPI 加速与断点续传](/handbook/install#国内网络-smapi-加速与断点续传)。

## Steam 邀请码卡没有显示 / 一直等待 / 显示 Auth 异常

- 全新实例默认没有 Steam 邀请码卡，这是“尚未启用”而不是故障。需要时由管理员停服后在“安装”页按需启用；未启用实例不会请求或轮询邀请码。
- 已启用实例在服务器未运行时会提示先启动；启动过程中和 Auth 刚就绪时显示等待或正在生成都属于正常状态。邀请码走 Steam SDR / Galaxy P2P 中继，生成速度可能受网络环境影响。
- 显示“Auth 异常”表示可选的邀请码链路暂时不可用，不代表服务器或游戏安装失败。可以继续使用“总览”“服务器”页以及移动首页始终显示的**局域网直连**信息；面板默认开启 `Server.AllowIpConnections`，开放 `UDP 24642` 后即可用 IP 加入。
- “局域网直连”地址根据你当前访问面板所用的主机名或 IP 生成，不负责自动发现公网 IP。异地玩家无法连接时仍需检查云安全组、路由器端口转发和防火墙。

## 更新到 v0.6.0 后 Steam 邀请码会怎样

- 旧实例如果历史上已经成功完成 SteamAuth 授权或已有邀请码能力，升级后会继续保持启用，不会突然隐藏或停止原有邀请码链路。
- 只有普通安装或 SteamCMD 授权记录、从未启用过邀请码的实例会保持关闭；升级后的启动、状态检查和日常升级不会强制拉取或校验 Auth。
- 升级和修改 Steam 账号密码都不会主动删除已有的有效 SteamCMD 授权缓存或 SteamAuth session。SteamCMD 无法继续使用缓存时才回退到当前保存的凭据；已经完成授权的 Auth session 不会因修改凭据被主动替换。

## 好友/局域网玩家进不去游戏

- 最常见原因是只开放了 TCP 端口，漏了 UDP：Stardew 游戏端口 `UDP 24642` 和查询端口 `UDP 27015` 都必须放行，且必须是 UDP 而不是 TCP。
- 云服务器检查安全组规则；NAS 检查路由器端口转发是否把 `UDP 24642`/`UDP 27015` 转发到 NAS 的局域网 IP。
- 确认游戏内/面板里显示的服务器状态是"运行中"，而不是仍在安装或启动过程中。
- 完整端口说明见 [端口与安全组](/deploy/ports)。

## "当前激活存档"信息显示"未知"

- 刚新建存档时，游戏还没有触发过第一次自动存档（游戏内过夜/睡觉），面板暂时读不到农场主、日期等信息，属于正常的短暂中间状态，等游戏内过一天就会显示正常。
- 如果长时间（远超一次正常存档创建耗时）仍然显示"未知"，且局域网/邀请码都能正常进入游戏，说明游戏本身没问题，只是面板存档指针识别出现异常；更新面板到最新版本可以让这种情况自动修正，无需手动处理。

## 复制按钮（邀请码 / 局域网直连）点击没反应

- 早期版本在通过 `http://IP:端口`（非 HTTPS）访问面板时，浏览器复制 API 不可用会导致复制按钮没有任何反应。更新面板到最新版本即可修复，复制按钮会自动降级使用兼容方案。

## Mod 相关：Nexus 搜索/安装失败

- Nexus 数字 ID 精确查询需要先在"模组"页配置管理员的 Nexus API Key；未配置时会明确提示缺少 Key，而不是报错 500。普通关键词搜索不需要配置 Key。
- 通过浏览器扩展一键安装 Mod 时，确认扩展已更新到面板提示的最新版本（扩展版本和面板不匹配可能识别不到 Nexus 页面的下载入口）。
- 批量安装多个 Mod（含前置）时，如果某个 Mod 之前已经安装过又被重复提交，面板会自动识别为"已安装，跳过重复导入"，不会算作失败。
- 更多 Mod 操作说明见 [Mod 管理](/maintain/mods)。

## 存档启动失败

- 提示需要选择存档（`save_required`）：说明服务器已经安装好，但还没有可用存档，回到"存档"页新建或上传一个。
- 首次新建时如果提示 SMAPI 内置组件同步失败，说明面板在启动服务器前的完整性检查中安全停止了。先检查 Docker、游戏数据卷和磁盘空间，再直接重试；v0.4.11 不会在这种失败下覆盖玩家 Mod 或留下半成品存档事务。
- 提示 VNC 端口不可用：说明宿主机上 VNC 端口（默认 `5800`）被占用，检查是否有其他程序占用该端口，或在设置里更换端口。

## 更新面板后版本没有变化

- 普通更新只会在本地已有对应镜像层时生效；如果拉取失败或使用了旧缓存，需要强制更新：

```bash
cd ~ && bash run.sh force-update
```

- 如果一键脚本本身也有更新，先更新脚本再更新面板：

```bash
cd ~ && bash run.sh update-script
cd ~ && bash run.sh update
```

## 还是没解决？

在"诊断"页导出诊断包（管理员可见），里面包含版本、健康检查、任务日志、Compose 状态等信息（已自动脱敏密码/Token），反馈问题时附带诊断包能大幅加快排查速度。
